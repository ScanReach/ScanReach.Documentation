# ConnectPOB Troubleshooting FAQ

## System Issues

<details>
<summary>What should I do if a node shows offline status?</summary>
If a node appears offline:
<ol>
<li>Check the physical connection and power supply to the node</li>
<li>Verify the node is within range of the mesh network</li>
<li>Check for any error indicators on the node hardware (LED status)</li>
<li>Review the mesh debug tool for connectivity issues</li>
<li>Try restarting the node by disconnecting and reconnecting power</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

<details>
<summary>What should I do if the ConnectPOB system is not responding?</summary>
If the ConnectPOB system is not responding:
<ol>
<li>Check if the gateway computer is powered on</li>
<li>Verify the gateway computer has network connectivity</li>
<li>Ensure the root node is properly connected to the gateway</li>
<li>Check if there's a power outage affecting the system</li>
<li>Try accessing the system from a different device or browser</li>
<li>Restart the gateway computer if necessary</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

<details>
<summary>What should I do if the system shows incorrect time?</summary>
If the system shows incorrect time:
<ol>
<li>Verify the gateway computer has internet connectivity for time synchronization</li>
<li>Check the time zone settings in the system configuration</li>
<li>Ensure the gateway computer's system time is correct</li>
<li>Restart the ConnectPOB service if necessary</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

## Wearable Issues

<details>
<summary>What should I do if a wearable is not being detected by the system?</summary>
If a wearable is not being detected by the system:
<ol>
<li>Verify the wearable has been properly activated (press and hold for 1-3 seconds until green LED blinks)</li>
<li>Check that the wearable has been assigned to a person in the system</li>
<li>Ensure the person has been embarked in the system</li>
<li>Verify the wearable is within range of a mesh node</li>
<li>Check the battery status of the wearable (may need replacement if depleted)</li>
<li>Try reactivating the wearable by pressing and holding again</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

<details>
<summary>What should I do if a wearable's battery is draining quickly?</summary>
If a wearable's battery is draining quickly:
<ol>
<li>Check if the wearable has been accidentally activated (look for blinking LED)</li>
<li>Verify the wearable is not being stored in a location with extreme temperatures</li>
<li>Ensure the wearable is not being pressed or compressed in storage</li>
<li>Check if the wearable has been damaged or exposed to water</li>
<li>Replace the wearable if it has been in use for close to 24 months (typical lifespan)</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

<details>
<summary>What should I do if a distress alarm is not triggering properly?</summary>
If a distress alarm is not triggering properly:
<ol>
<li>Verify the correct activation method (press and hold for +1 second until red LED blinks)</li>
<li>Check that the wearable has been properly activated (green LED should blink when activated)</li>
<li>Ensure the person associated with the wearable is embarked in the system</li>
<li>Verify the mesh network is functioning properly</li>
<li>Check if the distress alarm is being triggered but not displaying on the dashboard</li>
<li>Test with a different wearable to isolate the issue</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

## Personnel Management Issues

<details>
<summary>What should I do if I can't add a new person to the system?</summary>
If you can't add a new person to the system:
<ol>
<li>Verify you have the necessary permissions to add personnel</li>
<li>Check that all required fields are filled in correctly</li>
<li>Ensure there are no duplicate entries for the same person</li>
<li>Verify the system is not in maintenance mode</li>
<li>Try refreshing the page and attempting again</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

<details>
<summary>What should I do if a person's status is not updating correctly?</summary>
If a person's status is not updating correctly:
<ol>
<li>Verify the person's wearable is properly activated and functioning</li>
<li>Check that the wearable is assigned to the correct person</li>
<li>Ensure the person is within range of a mesh node</li>
<li>Verify the mesh network is functioning properly</li>
<li>Check if there are any system-wide connectivity issues</li>
<li>Try reassigning the wearable to the person</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

<details>
<summary>What should I do if a person shows as "UNRESOLVED" status?</summary>
If a person shows as "UNRESOLVED" status:
<ol>
<li>Understand that "UNRESOLVED" means the person is created and managed from an external crew management system (OCS or Unisea)</li>
<li>Verify the person is embarked but not yet assigned a wearable in ConnectPOB</li>
<li>For OCS systems: wearable assignment should be handled in ConnectPOB</li>
<li>For Unisea systems: wearable assignment is handled in the Unisea system</li>
<li>Assign a wearable to the person in the appropriate system</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

## Bunk Management Issues

<details>
<summary>What should I do if I can't assign a bunk to a person?</summary>
If you can't assign a bunk to a person:
<ol>
<li>Verify the person has been added to the system</li>
<li>Check that there are available bunks in the system</li>
<li>Ensure the bunk is not already occupied or disabled</li>
<li>Verify the person's embarkation dates are compatible with the bunk availability</li>
<li>Check if there are any system restrictions preventing the assignment</li>
<li>Try refreshing the page and attempting again</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

<details>
<summary>What should I do if a bunk shows an issue with muster stations?</summary>
If a bunk shows an issue with muster stations:
<ol>
<li>Verify the assigned muster stations still exist in the system</li>
<li>Check if the muster stations have been disabled or removed</li>
<li>Update the bunk configuration with valid muster stations</li>
<li>Ensure the muster stations are properly configured in the system</li>
<li>Verify the muster stations are active for the current muster type</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

<details>
<summary>What should I do if I can't disable a bunk?</summary>
If you can't disable a bunk:
<ol>
<li>Verify there is no person currently checked in to the bunk</li>
<li>Check if there are future reservations for the bunk</li>
<li>Move any future reservations to other bunks before disabling</li>
<li>Ensure you have the necessary permissions to disable bunks</li>
<li>Try refreshing the page and attempting again</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

## Muster Station Issues

<details>
<summary>What should I do if muster stations are not detecting personnel?</summary>
If muster stations are not detecting personnel:
<ol>
<li>Verify the muster station nodes are properly powered and functioning</li>
<li>Check that the nodes are configured as muster stations in the system</li>
<li>Ensure the muster stations are activated for the current muster type</li>
<li>Verify personnel have working wearables that are properly activated</li>
<li>Check the retention level settings for the muster stations</li>
<li>Ensure personnel are within range of the muster station nodes</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

<details>
<summary>What should I do if the mustering process is not starting?</summary>
If the mustering process is not starting:
<ol>
<li>Verify you have the necessary permissions to start mustering</li>
<li>Check that the system is not already in a mustering state</li>
<li>Ensure all required muster stations are properly configured</li>
<li>Verify the mesh network is functioning properly</li>
<li>Try refreshing the page and attempting again</li>
<li>Check if there are any system-wide issues affecting mustering</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

<details>
<summary>What should I do if personnel are not being marked as "Accounted For" during mustering?</summary>
If personnel are not being marked as "Accounted For" during mustering:
<ol>
<li>Verify the "Auto count" feature is enabled (default is ON)</li>
<li>Check that personnel are within range of active muster station nodes</li>
<li>Ensure the muster stations are activated for the current muster type</li>
<li>Verify personnel have working wearables that are properly activated</li>
<li>Check the retention level settings for the muster stations</li>
<li>Try manually registering personnel using the "Manually Register" toggle</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

## Tablet Issues

<details>
<summary>What should I do if the tablet is not connecting to the ConnectPOB system?</summary>
If the tablet is not connecting to the ConnectPOB system:
<ol>
<li>Verify the tablet is connected to the same Wi-Fi network as the gateway computer</li>
<li>Check that the URL is entered correctly (http://your-vessel-domain-name.edge.scanreach.com/tablet)</li>
<li>Ensure the tablet has a stable internet connection</li>
<li>Try restarting the tablet and reconnecting to the Wi-Fi network</li>
<li>Verify the gateway computer is powered on and functioning</li>
<li>Check if there are any network-wide connectivity issues</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

<details>
<summary>What should I do if the tablet is not showing distress alarms?</summary>
If the tablet is not showing distress alarms:
<ol>
<li>Verify the tablet is powered on and the ConnectPOB application is running</li>
<li>Check that the tablet is connected to the ConnectPOB system</li>
<li>Ensure the tablet is within sight and turned on at all times (as required)</li>
<li>Verify the distress alarm is being triggered properly from the wearable</li>
<li>Check if the tablet's volume is turned up and not muted</li>
<li>Try restarting the ConnectPOB application on the tablet</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

<details>
<summary>What should I do if the tablet is not displaying mustering information?</summary>
If the tablet is not displaying mustering information:
<ol>
<li>Verify the tablet is connected to the ConnectPOB system</li>
<li>Check that a mustering process has been started from the main system</li>
<li>Ensure the tablet has the latest mustering data (try refreshing)</li>
<li>Verify the tablet is not in an emergency state (distress alarm)</li>
<li>Try navigating back to the main view and then to mustering again</li>
<li>Restart the ConnectPOB application on the tablet</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

## Distress Alarm Issues

<details>
<summary>How do I set up the Distress Alarm hardware?</summary>
To set up the Distress Alarm hardware:
<ol>
<li>Find a suitable location on the bridge (or other 24/7 manned areas) that is easily visible and close to a power outlet</li>
<li>Connect the distress alarm box cable to the corresponding end on the mesh node, gently securing the screw locking by hand until you feel resistance</li>
<li>Connect the power supply to the mesh node using the provided USB cable</li>
<li>Power on the hardware by connecting the power supply to the outlet</li>
<li>Note down the MeshNode's MAC address (you'll need it later for registration)</li>
<li>Mount the hardware in the chosen location using the Velcro strips</li>
</ol>
Note: The Distress alarm node should always be connected to an UPS to make sure there is an audible alarm when there is a power outage.
</details>

<details>
<summary>What should I do if the Distress Alarm hardware is not working?</summary>
If the Distress Alarm hardware is not working:
<ol>
<li>Verify the Distress Alarm node is properly powered</li>
<li>Check that all cables are securely connected</li>
<li>Ensure the node is configured as an Alarm Node in the system</li>
<li>Verify the mesh network is functioning properly</li>
<li>Check if the distress alarm is being triggered but not activating the hardware</li>
<li>Try restarting the Distress Alarm node by disconnecting and reconnecting power</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

<details>
<summary>What should I do if a distress alarm is not being acknowledged properly?</summary>
If a distress alarm is not being acknowledged properly:
<ol>
<li>Verify you are clicking the "acknowledge" button in the alarm details</li>
<li>Check that you have the necessary permissions to acknowledge alarms</li>
<li>Ensure the alarm is not already in a resolved state</li>
<li>Try refreshing the page and attempting to acknowledge again</li>
<li>Check if there are any system-wide issues affecting alarm management</li>
<li>Try acknowledging the alarm from a different device or browser</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

## Gangway Issues

<details>
<summary>What should I do if the gangway system is not detecting personnel?</summary>
If the gangway system is not detecting personnel:
<ol>
<li>Verify personnel are holding their wearable correctly (on their right hand)</li>
<li>Ensure personnel are holding their wearable close enough to the box</li>
<li>Check that the gangway boxes are properly powered and functioning</li>
<li>Verify the mesh nodes connected to the gangway boxes are online</li>
<li>Check the sensitivity settings for the gangway configuration</li>
<li>Ensure the gangway is activated in the system</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

<details>
<summary>What should I do if the gangway system is showing incorrect transfer locations?</summary>
If the gangway system is showing incorrect transfer locations:
<ol>
<li>Verify the vessel location is correctly set in the gangway configuration</li>
<li>Check if the NMEA GPS node is properly connected and functioning</li>
<li>Ensure the drop-off location is correctly configured for the gangway</li>
<li>Try manually correcting the transfer location in the transfer listing</li>
<li>Verify the gangway configuration settings are correct</li>
<li>Check if there are any system-wide location issues</li>
<li>Contact support if the issue persists</li>
</ol>
</details>

<details>
<summary>What should I do if the gangway traffic light is not working correctly?</summary>
If the gangway traffic light is not working correctly:
<ol>
<li>Verify the traffic light hardware is properly connected to the gangway box</li>
<li>Check that the traffic light is properly powered</li>
<li>Ensure the gangway configuration includes the correct traffic light hardware</li>
<li>Verify the yellow-light and red-light personnel limits are correctly set</li>
<li>Check if the emergency stop has been activated</li>
<li>Try restarting the gangway system</li>
<li>Contact support if the issue persists</li>
</ol>
</details>
